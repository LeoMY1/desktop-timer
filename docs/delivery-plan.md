# 分阶段交付与用户验收

版本：2026-09-18。用户已授权 P4；P4 v2 修复版待验收，P5 尚未授权。

## 执行规则
每次只做一阶段：**实施本阶段 → 自测 → 交付成果及操作清单 → 用户测试/审查 → 用户明确确认通过并允许继续 → 下一阶段**。
任何阶段被要求修改，先修复和重新交付；不并行开展下一阶段。用户没有回复时停止等待。内部自测与用户验收分开记录。

“预计交付”是该阶段的成果承诺，不表示这些文件现在已经存在。每阶段必须说明哪些功能已可用、哪些仍待后续阶段；不得将原型展示包装成已完成业务功能。

## P1：文档审查步骤（已进入 P2）
1. 阅读需求文档，重点核对：日累计、暂停/停止的区别、零点继续、睡眠继续、异常恢复。
2. 核对记录规则：按日累计整小时触发，每次停止形成独立学习段，尾段单独或合并不重复计时。
3. 核对视觉修订：卡片上方、空间不足临时下移并恢复、时长用中文单位、隐藏时区标签。
4. 阅读 spec，确认其为拟定实现方案，并检查有没有改变业务规则。
5. 阅读本文件，确认每一步交付范围和用户验收方式。
6. 若有问题，指出条目并要求修改；只有你明确确认 P1 通过并允许继续，才开始 P2。

P1 当时只交付文档。用户后续明确要求“按照文档，完成P2开发”，作为进入 P2 的授权；不推断为后续阶段授权。

## P2：原生交互原型验收
本次可运行交付与具体步骤见 [P2 测试清单](p2-testing.md)，真实验证范围见 [自测记录](p2-self-test.md)。
只交付窗口和交互。时间及历史内容使用明确标记的演示数据，不写入真实学习数据库。
| 操作 | 预期 |
|---|---|
| 双击原型，切换到浏览器和编辑器 | 主悬浮窗可见，窗口之外正常操作 |
| 在编辑器持续输入，触发演示备注卡片 | 卡片出现在上方，输入仍留在原应用 |
| 主动点击备注输入区 | 可以输入中文、选择文字并编辑 |
| 从主窗四边或非交互空白处拖至屏幕顶端后打开卡片 | 主窗临时下移，卡片仍在上方；收起后恢复 |
| 卡片打开期间主动拖动，再关闭卡片 | 保留用户新位置，不突然跳回 |
| 切换全屏浏览器与不同桌面 | 主窗保持可见，切换顺畅 |
| 切换系统深浅色，打开历史演示窗 | 文本清晰，最新视觉修订一致 |
| 隐藏主窗并从菜单栏恢复 | 能找回窗口；原型中不声称已验证真实计时 |

交付时列出本机已测场景与未测环境。P2 原型的演示入口不得混入最终用户界面。

## P3：计时与本地保存验收
本次交付见 [P3 测试清单](p3-testing.md) 和 [P3 自测记录](p3-self-test.md)。
本阶段接入真实计时、状态、日累计和持久保存，记录窗口提供必要的时长概览；整小时鼓励与完整备注交互留在 P4。
| 操作 | 预期 |
|---|---|
| 开始，等待超过 1 分钟，暂停，再继续 | 运行时间增加，暂停时间不计入 |
| 停止后再次开始 | 新建学习段，今日累计保留 |
| 正常退出，稍后重新打开 | 原记录存在，退出期间不计入，初始为停止 |
| 使用隔离数据的异常退出验收 | 仅恢复最后检查点，不补算关闭间隔 |
| 锁屏或睡眠后恢复 | 运行中的时长正确累计 |
| 查看隔离时钟的午夜验收结果 | 按日拆分；运行连续，暂停不自动恢复 |

长时间和跨午夜用例允许采用明确标注的隔离时钟测试，并同时交付简短真实时间操作供用户核对；不改动电脑系统时间，也不污染用户数据库。

## P4：鼓励与记录验收
本次成果与操作见 [P4 测试单](p4-testing.md)，证据见 [P4 v2 自测记录](p4-v2-self-test.md)。
| 操作 | 预期 |
|---|---|
| 在隔离测试环境推进到累计整小时 | 一次无声动效，卡片向上出现 |
| 在卡片中持续输入并跨过新时间边界 | 计时继续，草稿不被新提醒覆盖 |
| 稍后填写，进入历史页编辑并重启 | 备注及修改仍在 |
| 90 分钟结束后合并尾段，再开始 30 分钟 | 日总计 2 小时，两学习段独立，无重复覆盖 |
| 不满一小时停止且没有上一条 | 能单独记录，不允许跨段合并 |
| 自动结束或模拟零点 | 尾段默认并入本段上一条，没有上一条则新建 |
| 跳过多个整小时后恢复显示 | 提醒合并，条目保留且不重复弹出 |
| 保存或存储异常用例 | 明确显示错误，不假称保存成功，不覆盖旧库 |

## P5：最终回归与交付
重新验证已经验收的核心流程；去除原型专用入口，检查真实用户数据隔离、安装/启动说明与已知限制。
最终 .app 至少在当前 Mac 验证；没有测试过的 macOS 或机型不得宣称已全面兼容。交付成果在项目 outputs 内版本化存放，不覆盖用户历史记录。
用户测试通过后再记录最终验收完成。
