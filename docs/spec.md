# MVP 技术规格

版本：2026-09-18，P2 交付补充。计时、存储和完整记录仍为后续阶段方案；当前只实现原生窗口与固定演示交互，详见第 8 节。

## 1. 技术与职责
采用 Swift + SwiftUI + AppKit，最低 macOS 13，首个验收目标为当前 arm64 Mac。拟使用 Swift Package 和命令行工具链构建，以本地 SQLite 持久保存，不引入服务端或第三方依赖。

| 模块 | 职责 |
|---|---|
| TimerEngine | 开始、暂停、继续、停止，阈值与午夜结算；不依赖 UI |
| TimeSource | 生产环境连续计时，测试环境可控推进 |
| LedgerStore | 原子读取/保存、版本校验、错误处理 |
| ReminderCoordinator | 整小时去重、排队和合并展示；不控制计时状态 |
| WindowController | 悬浮层级、焦点、位置、弹窗与历史窗口 |
| Views | 状态、时间、备注与记录页呈现 |

拟定代码入口、构建脚本和测试文件只在对应开发阶段获准后创建，P1 不创建 Package.swift、Sources、Tests 或应用包。

## 2. 状态与时间
| 当前状态 | 操作/事件 | 结果 |
|---|---|---|
| stopped | 开始 | 新建当前日期学习段，进入 running |
| running | 暂停 | 结算到操作时刻，进入 paused |
| paused | 继续 | 恢复累计；若已跨日则新建当前日期学习段 |
| running / paused | 停止 | 结束学习段、保存、进入 stopped |
| running | 零点 | 结束昨日段，处理尾段；新日创建学习段并继续 |
| paused | 零点 | 结束昨日段，不补计暂停时间，保持暂停 |
| stopped | 零点 | 显示新日累计，不开始计时 |
| 任意 | 正常退出 | 结算正在运行的部分、保存并停止 |
| 恢复启动 | 上次异常关闭 | 保留最后检查点，归档未结束段，进入 stopped |

运行中的时长基于 ContinuousClock，覆盖系统睡眠，不依赖每秒回调是否准时；使用启动时的日期锚点与连续经过时间投影当前时间。日期使用固定 Asia/Shanghai 日历。
时间推进逐一处理经过的午夜和当日累计整小时边界；暂停只处理归日，不累计时间。检查点不能在下次进程启动时被解释为一直运行至今。
内部保存秒级精度；格式化时才舍去不足一分钟的显示部分。不得逐次舍入小时间片后再累加。

## 3. 数据关系与存储
| 数据 | 主要内容 |
|---|---|
| StudySession | ID、学习日期、开始/结束、结束原因、累计秒数、有效间隔、内容条目 |
| StudyInterval | 有效运行的开始/结束；暂停产生间隔 |
| LearningEntry | ID、段内开始/结束累计秒偏移、文字、尾段待处理标记 |
| HourlyMilestone | 日期＋累计小时序号唯一键、关联条目、达成时刻、展示状态 |
| Ledger | 数据版本、全部学习段和里程碑、当前状态和学习段、检查点 |

条目的累计偏移不能交叉重叠，不能超过学习段有效时长。每天的总时长从学习段汇总，不从备注数量或文字推导。
MVP 拟将版本化 Ledger JSON 快照存入 SQLite，以一次事务同步保存计时状态、备注、尾段和里程碑。启用 WAL、FULL 同步及 busy timeout；事务失败不覆盖上次成功快照。
初始版本为 1；损坏、未知版本及不一致引用拒绝读取并保留原文件。当前没有既有用户数据库，因此首版不包含迁移旧产品数据的工作。
默认保存位置拟为用户 Library/Application Support/StudyTimer/study.sqlite3；STUDY_TIMER_DATA_DIR 用于明确隔离的测试/演示数据。避免同一数据目录被多个写入进程同时使用。

## 4. 小时记录、尾段和草稿
达到累计阈值时，为当前学习段尚未归入条目的有效偏移创建新条目并保存唯一里程碑。连续跨过多小时则逐一生成条目，展示时合并提示，不丢记录。
自动尾段扩展同一段上一条目的结束偏移；没有上一条则新增。手动尾段先持久保存待处理条目，选择合并时拼接保留两条文字，选择单独时只改变待处理状态；两种操作都不改变日累计。
备注编辑与计时并行，草稿写入模型并短延迟保存；关闭卡片、结束编辑、退出时强制保存。未填写正文的条目仍可从历史记录补填。
提醒排队展示，当前输入不被替换；显示时按持久化标记去重。主窗隐藏或系统不能展示提示时保留待填写记录，恢复展示后合并提示。

## 5. 窗口与交互
- 主窗初始设计约 280×158 pt，使用 NSPanel + nonactivatingPanel、floating、canJoinAllSpaces、fullScreenAuxiliary，切换应用不隐藏。主窗不成为主要输入窗口。
- 整小时备注为独立 panel，位于主窗上方，按钮和时间始终可见；仅用户点击文本输入时获取键盘焦点。
- 顶部不足空间时记录原坐标并临时下移主窗；卡片关闭恢复原坐标。主动拖动则取消自动恢复，记住用户的新位置。
- 保存用户主动设置的位置；系统自动位移不覆盖原位置。显示器移除后校正到当前可见区域。
- 历史窗口初始约 840×620 pt，可调整尺寸，按日期侧栏、学习段分组和内容条目组织；用户主动打开时才激活应用。
- 手动停止后的尾段卡片参照已审查的状态图紧邻计时窗展示，不遮挡时间与按钮。
- 鼠标只在窗口实际区域被处理，不使用覆盖全屏的透明遮罩。

## 6. 视觉与反馈
主窗保持 HH:MM；历史时长用中文单位，未满一分钟用“不足1分钟”。界面不显示“北京时间”标签。
浅色以 design/p0/v3 为准，深色以 v1 状态结构为参考并同步最新修改。使用低饱和青绿色，柔和星光约 2 秒，不播放声音。具体尺寸、深色对比和输入体验在 P2 交付中由用户实测。
保存失败提供明显错误及重试，不显示虚假的已保存状态。若退出保存失败，允许留在应用或明确选择仍然退出。加载失败说明错误并保留原文件。

## 7. 验证与阶段限制
P2 只实现可运行的交互原型，以明确标注的演示数据验证窗口与焦点，不宣称已经具备真实计时和持久保存。
P3 验证核心计时、归日、保存和恢复；P4 才实现完整整小时、尾段与备注流程；P5 做累计回归与发布交付。每一步先交付，再等待用户测试和明确放行。
自动化测试采用隔离数据库和可控时钟，窗口验收采用真实应用操作。未执行的全屏、休眠、跨天等场景不得写为已经通过。

## 8. P2 实际实现与边界
用户明确授权 P2 后，建立 `Sources/StudyTimerPrototype`、独立 `WindowGeometry` 模块、布局检查与打包脚本。本阶段没有 TimerEngine、TimeSource、LedgerStore 或真实 ReminderCoordinator，也没有 SQLite 和学习记录持久化。

- v2 主窗四周边缘、数字和非交互空白处均为拖动区；依据按钮实际布局排除交互控件。仅实际位移取消卡片关闭复位。
- 主窗 288×176 pt；备注卡片 288×244 pt，固定在主窗上方，间距 3 pt；屏幕可见区域保留 8 pt 边距。历史窗口初始 850×620 pt。
- 主窗为非激活 NSPanel，不能成为键盘窗口。备注 panel 展示只调用 orderFront；原生 NSTextView 在用户主动点击时请求键盘焦点。
- 顶部空间不足保存原坐标、临时下移，收起恢复；实际拖动才取消恢复，仅点击拖动区域不取消。拖动结束校正到屏幕内。屏幕变化时恢复可见位置。
- 日累计、历史、整小时和尾段全部为示例；开始/暂停/停止只改变演示状态。8 秒延迟和约 2 秒星光仅用于界面验收。
- 草稿和历史编辑仅放内存；保存提示明确注明“仅本次运行”。合并/单独记录只演示选择反馈，不创建或合并实际数据。
- `local.study-timer.p2` 是独立 bundle ID，只用 UserDefaults 保存窗口位置；自查模式不读写该位置。
- 外观默认跟随系统；验收菜单可临时强制浅色/深色，重启恢复跟随系统，不修改系统外观设置。
- 本机 CLT 工具链无法查询 SDK PlatformPath，故脚本直接调用 xcrun swiftc 构建 arm64/macOS 13，再打包并本地 ad-hoc 签名。未做 Developer ID 公证或其他机型验证。

这组实现用于 P2 测试，不改变前文未来 MVP 的业务规则。最终版本需在 P5 移除原型演示菜单。真实全屏/Spaces、输入法候选框等用户操作验收状态单独记入 p2-self-test.md，不以 NSPanel 标志检查替代。
