# Agent 协作流程

项目长期规则在根目录 AGENTS.md；此处说明如何实际使用。

1. 先检查当前实现及需求。每轮最多问五个问题，只询问业务偏好、冲突或无法从代码发现的信息。
2. 先交付计划：目标、范围、实现方式、阶段交付和验收点。视觉变化先给出可审查的设计。
3. 用户授权当前阶段后实施。持续汇报新发现与尚未解决事项，不把“下一步”扩大为全部阶段。
4. 以隔离数据运行适当检查。清楚区分可控时钟、真实运行、用户反馈及未测项；保存失败不能假称成功。
5. 交付可运行结果、操作步骤、测试证据和限制，等待用户明确通过。出现反馈先修复当前阶段。
6. 发布或清理遵循已授权范围。先审查拟公开内容和全部历史，再推送、远端克隆核验，最后清理可恢复产物。

## 文档职责
AGENTS.md 存稳定规范，requirements.md 存产品规则，spec.md 存当前实现契约，validation.md 存验证边界，development-case.md 存过程案例，stages.md 存快照索引。需求变更需同步相关文档，不堆进 AGENTS.md。

## 阶段交付参考
P0 设计审查 → P1 文档 → P2 原生交互 → P3 计时与保存 → P4 内容与提醒 → P5 累计回归。新贡献可采用更小阶段，不要求重新执行全部历史流程；范围与验收必须事先明确。

## 开源贡献
先说明要解决的具体问题及操作路径，再修改对应模块；更新受影响的需求/规格。构建与测试入口见 README。UI 问题附隔离测试内容，不能附真实学习数据库、个人信息或密钥。PR 描述说明结果、验证及未测范围，避免宣称尚未完成的兼容性。
