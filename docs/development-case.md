# 从需求到原型：Agent 开发案例

本案例来自已交付阶段与验收记录的整理，不包含原始对话。Git 阶段快照为事后导入，不是原开发逐操作提交。

## 先把交付边界说清楚
目标是本地 macOS 悬浮学习计时。最初只有开始、暂停、日累计等方向，随后明确按北京时间归日、睡眠持续累计、正常退出停止、异常只恢复检查点，以及小时记录和尾段的归属。

流程采用视觉审查、文档定稿、交互原型、计时存储、提醒备注、最终回归，每步先交付给用户测试，不能因为一次“继续”就跨越多个阶段。早期曾错误扩大阶段范围，后续将这一约束明确写入唯一的根 AGENTS.md。

## 视觉审查改变了实现
用户要求小时卡片位于整个计时窗上方；历史中钟点和时长需可区分，并移除界面时区标签。顶端空间不足时采用临时下移，关闭卡片恢复，用户主动拖动后保留新位置。设计稿先形成审查基线，再进入原生实现。

P2 用户反馈只能拖动左上文字，随后扩大到四边、数字和空白区域，排除按钮命中；右上菜单和历史按钮统一完整 20×20 点击范围。单纯设置 NSPanel 属性无法替代用户实际操作。

## 计时与存储需要可控边界
P3 将连续时钟、引擎、SQLite 与 UI 分开。用可控时钟检查 25＋35、90＋30、23:40 至 00:20、暂停和恢复；另用真实等待及独立进程异常结束验证检查点。模拟通过与真实午夜/睡眠分别记录。

P4 将日累计整小时提醒与学习段归属分开。尾段先持久化，合并只变更内容覆盖范围；总时长继续来自有效区间。新提醒排队，避免覆盖草稿。测试曾发现旧草稿缓存遮住合并后文字，修复后增加界面读取与持久值一致的回归。

## 模拟入口本身也会造成误解
旧验收入口复用固定 09:00 的自动化时钟，跨日快进又将跳过的时间计入持续学习，使测试结果像是开始钟点错误和昨日累计异常。排查区分了模拟库与正式库。

修复交互验收的时钟锚点和说明后，最终日常版本进一步移除模拟入口，内部测试单独构建。用户还要求星光开始闪烁三次、停留三十秒，并移除可能被误认为全局操作的退出快捷键。

## 开源整理的要求
交付 ZIP 并不天然是可维护的开源项目：历史脚本、重复配置和个人验收证据需分离。当前仓库统一构建/测试/打包，公开整理后的规范、需求和案例，将历史实现在独立提交中保留。先推送并干净克隆验证，再清理本地重复产物。

这次经历形成的规则是：业务歧义先讨论；设计和阶段交付可审查；验证事实有明确来源；公开项目应能脱离开发者本机缓存运行。当前仍定位为原型，自然跨午夜和其他机型不能因已有自动化就标为通过。
